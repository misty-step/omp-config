# Native dispatch route matrix

Route by the observable outcome.
The chief owns intent, shared contracts, integration, and final judgment.
Each native agent owns one bounded lane.

## Routes

| Outcome | Native agent | Method or skill | Oracle |
|---|---|---|---|
| system architecture | `architect` | `project-engineering`, `mcp-design`, or `vision` when needed | boundary proposal, dependency graph, and reversal condition |
| accepted implementation | `builder` | `deliver`, `ci`, and domain skills named in the brief | real entrypoint plus required repository gate |
| security or code review | `verifier` | `review-security`, `code-review`, or `review-tests` | ranked finding with a reproducible trigger or static evidence |
| live QA | `verifier` | `verify-live` | live result against the acceptance oracle |
| incident reproduction | `verifier` | `verify-live` and the named operations skill | original failure replay plus live signal |
| broad research | `researcher` | `research`; add `peer-harnesses` for model facts | cited source packet and uncertainty statement |
| external API research | `researcher` | `research` and official documentation | primary citation and runnable request shape |
| UI or product design | `designer` | `design`, `improve-ui`, or `baseline-ui` | rendered inspection and acceptance evidence |
| persona QA | chief → `qa-user` → `qa-user-leaf` | `qa-users` | real local, dev, or staging browser scenarios |

The five broad agents are `architect`, `builder`, `verifier`, `researcher`, and
`designer`.
`qa-user` and `qa-user-leaf` exist only for the required persona depth.

## Method consolidation

Put repository inventory, API research, library research, and source synthesis
in a `researcher` brief.
Put code review, security review, live verification, and incident reproduction
in a `verifier` brief.
Do not create durable method-specific agents.

Use the chief for cross-lane coordination.
Do not insert a coordinator between the chief and an executive.
Dispatch multiple agents only when their work is independent.

## Native execution

OMP selects the model, tools, and autoloaded skills from each declaration.
The task brief supplies the outcome, scope, oracle, evidence, and non-goals.
The brief can narrow work by instruction.
It cannot add tools to the declaration.

OMP 17.2.3 cannot choose a different model or tool envelope for one native
spawn.
Do not emulate that feature with a process wrapper or generated declaration.
Change a durable agent ladder only when its normal work changes.

The only child route is `qa-user` → `qa-user-leaf`.
Every other native agent has no child authority.
Keep `task.maxRecursionDepth` at two.
Respect `task.maxConcurrency`.

| persona browser QA | `qa-users` | chief → `qa-user` → `qa-user-leaf` |

## MCP and tool routes

Use LSP for symbol intelligence.
Use browser for rendered behavior.
Use the live `parallel-search` MCP only for external research that needs it.
Follow `mcp-pruning.md` for every other MCP.
Use Mint for credentialed vendor calls.
Never put provider credentials in a task brief.

## Verification

Add one independent verifier for medium-risk work.
Add a verifier and review for high-risk work.
Unknown risk uses the medium-risk floor.
The verifier returns evidence and never repairs findings.
