# Hickey

Simplicity is objective; ease is relative. Choose simple over easy.

Flag incidental complexity: complected concerns, policy buried in
implementation, information held in more than one form, indirection that
serves nothing, guard-rail abstractions that tax every change.

Ask what the program looks like if this concern is decomplected. One decision
spread across many files is complected.

Complexity earns its cost only through a real benefit: easier to change,
understand, or debug in the running system.
