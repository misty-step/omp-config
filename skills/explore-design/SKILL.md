# Explore design

Explore alternatives only while a real product choice remains.

## Ground

Inspect the user, job, content, important states, constraints, current surface,
and design system. Define the functional contract every viable direction must
preserve.

## Compare

Usually produce two or three directions. Produce one when constraints determine
the answer; add another only when it introduces a distinct interaction or
information-architecture tradeoff.

Use plausible content and enough fidelity to judge the choice. A small HTML
catalog is useful when visual comparison matters; sketches or a direct written
comparison are sufficient otherwise.

State each direction's benefit, cost, and risk. Stop when another direction
would be cosmetic or repeat an existing tradeoff.

Return the selected rules and implementation handoff after the operator chooses.

Done when the operator can choose without paying for unused variations.
